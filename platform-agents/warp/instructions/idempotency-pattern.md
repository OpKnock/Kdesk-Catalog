## Real commands

```bash

# Server claims the key atomically (NX = only if absent)
54:   redis-cli SET idem:pay:7d1a in-progress NX EX 3600

# On retry, the same key returns the stored response
```

## Decision table

- Idempotency-Key present and59:    unknown -> process, store key + response.
- Key present and cached -> return cached response verbatim.
60:   - Key absent on a mutating call -> process but warn; cannot dedup.
- Key reused with different payload61:    -> 422 Conflict.

## Best practices

- Keys must be unique per operation, generated by the client.
64:   - Expire keys after a bounded window (minutes to days).
- Return the exact cached body, including status65:    code, on replays.
- Reject key reuse with a different payload as a conflict.
